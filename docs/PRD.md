## 1. Summary

这份文档说明言灵 v1.0.1 要做成什么。

打开产品时，先到「开始创建」落地页。用户说一句话，产品跳进工坊并自动发送。工坊仍按 v1.0.0 的规则：说话生成一份界面 JSON，渲染器按固定目录用 Ant Design 画成一页。同一份 JSON、同一个目录版本，永远画出同一页。

另外三页帮人看清目录、带走例子、配好对话通道：

- **基础组件：** 只读图鉴。18 个基础组件，每个有预览、合法 JSON、属性表。不新增组件。
- **精选案例：** 三个黄金任务。先看预览和 JSON，再点「用这一页」装进工坊。
- **设置：** 在浏览器里填 API Key、Base URL、模型名。填了就覆盖 `.env`；空着就用 `.env`。

v1.0.1 仍不做上线发布，不接真实接口，也不做多页应用。

## 3. Background

### 现在是什么情况

v1.0.0 把工坊写成了契约：对话主路径、目录校验硬闸、失败不覆盖、对话只说人话、JSON 可下载再打开。

仓库里已经能跑这条工坊。用户一打开就落在三栏编辑器里。要知道「目录里到底有什么」、要先看一页再接着改、没有 `.env` 时要自己配通道，都还没有产品入口。

A2UI Studio 把「开始创建」做成首页大输入，旁边是基础组件和卡片市场。A2UI Composer 把组件图鉴、案例和设置做成工作室的几页。这两边已经证明：生成器外面需要一层壳，否则目录和例子只能藏在提示词里。

### 为什么现在做 v1.0.1

工坊已经能证明「说话 → 合法 JSON → 稳定预览」。缺口变成三件小事，不是再扩目录：

- 人进门时面对编辑器，不像「生成式界面从这里开始」。
- 18 个组件只写在提示词和校验白名单里。工程师要核对属性，只能翻代码。
- 三个黄金任务是测试夹具，不是给人点开的案例。
- 对话通道只认进程里的 `.env`。没有环境文件的人，进不了主路径。

v1.0.1 补这层壳。目录版本仍是 v1.0.0 的基础目录。不加表格、菜单，也不做卡片市场。

## 4. Objective

### 目标

让人从一句话走进工坊，并且能先看懂目录和例子，再配好通道。

v1.0.0 的稳定含义全部保留：

- 模型只改 JSON，不直接画 HTML。
- 渲染器只画目录里允许的组件。
- 同一份 JSON，打开多少次都一样。
- 校验不过，页面保持原样。

v1.0.1 多三件事：

- 进门是落地页，不是编辑器。
- 目录和案例可以看、可以装进工坊，但不能改目录本身。
- 通道可以在页面上配，且覆盖关系说得清。

### 为什么重要

对使用产品的人：先说一句就能看到一页；不确定时可以先翻组件和案例，不必从空白猜。

对公司和团队：工坊仍是可重复能力。外壳只展示同一份协议 JSON，不另造一套页面格式。

这和产品方向一致：先证明「说话 → 合法 JSON → 稳定预览」，再让人看得见目录。仍不谈更大的目录、真实数据和上线。

### Key Results

v1.0.0 的 KR1～KR4 仍然有效。用例与切片见 [TEST](./TEST.md)（v1.0.1 需补外壳、图鉴、案例、设置用例）。

| 编号 | 结果 | 衡量方式 |
| --- | --- | --- |
| KR1 | 三类黄金任务都能用对话生成，并能再改一版 | 登录表单、设置页、带筛选的列表。每次结果都能通过目录校验，预览与 JSON 一致 |
| KR2 | 坏输出不能毁掉当前页 | 故意用不在目录里的组件、缺 root、非法属性。画布保持旧 JSON。对话里用人话说清原因 |
| KR3 | 文件往返后页面不变 | 下载 JSON → 清空现场 → 再打开同一文件。组件树、文案和数据与下载前一致 |
| KR4 | 对话主路径不像在看代码 | 成功时气泡里只有一句确认。完整 JSON 只出现在画布、底部编辑器和下载文件里 |
| KR5 | 落地页一句话能进工坊 | 在「开始创建」输入或点三个提示之一。进入工坊后这句话被自动发送。通过校验则纸页更新 |
| KR6 | 18 个基础组件都能在图鉴里看懂 | 每个组件有 Ant Design 预览、一份能过校验的 JSON、一张属性表。没有新组件名 |
| KR7 | 三个精选案例能预览，并能装进工坊 | 点「用这一页」后，工坊纸页与该案例 JSON 一致，且通过同一道校验闸 |
| KR8 | 设置页能改通道，且覆盖关系正确 | 界面有值则对话用界面的 Base URL / Key / 模型；三项都空则退回 `.env`。Key 只存在浏览器本地 |

## 5. Market Segment(s)

市场按「要完成的工作」划分，不按年龄或职级。

### 主工作：用说话做出一页能看的界面

这些人会说「做一个登录表单」「把按钮改成主色」。他们从落地页进门，要马上看到页面，不想先写 JSON。

约束：

- 只能用 v1.0.0 的基础目录，不能点名 Table、Menu 等 antd 组件。
- 一页一份 JSON，没有多页和路由页面。
- 预览可以试填、试点，但不会提交到真实后端。

### 次工作：看清目录，再把例子变成当前页

前端或熟悉协议的人要核对模型会用哪些组件、属性叫什么。他们需要图鉴。他们也要先看一页完整例子，再决定「用这一页」继续改。

约束：

- 图鉴是只读的。不能在图鉴里改目录、不能把单个组件插入当前页。
- 案例装入和对话改的是同一份文档，同样要过校验。

### 次工作：把对话通道配到能发

没有现成 `.env` 的人，要在设置里填 Base URL、Key、模型名，才能走主路径。

约束：

- 不切换渲染器，不接第二家模型品牌的专用 UI。
- 通道配置不是源文件的一部分。下载的 JSON 里不能出现 Key。

### 明确不做的工作（v1.0.1）

- 把页面发布成独立网址。
- 做成会自己变的应用（点击后模型再改界面）。
- 接真实接口、权限、多人协作。
- 扩目录（新组件、卡片市场、图标列表、协议生成器）。
- 传图识别。
- 图鉴里的移动端 / PC 预览切换。

## 6. Value Proposition(s)

### 用户要完成的工作

- 打开产品，说一句，立刻看到一页。
- 先翻组件和三个例子，再决定用哪一页继续说。
- 改一句，页面跟着改，而且改坏了还能停在上一版。
- 把这一页带走，以后打开还是这样。
- 没有 `.env` 时，也能在页面上把通道配好。

### 用户会得到什么

- 一条清楚的进门路径：落地页 → 自动发送 → 一句确认 → 预览更新。
- 一份可保存的 JSON。它就是页面本身，不是草稿备注。
- 一份和校验白名单相同的组件图鉴。预览外观仍是 Ant Design。
- 熟悉的 Ant Design 外观，同时不被 antd 的全部属性淹没。

### 用户能躲开什么痛苦

- 躲开「一进来就是编辑器，不知道从哪说起」。
- 躲开「模型写了一大段 HTML，每次都不一样」。
- 躲开「生成失败，当前页被盖掉」。
- 躲开「看起来能用，却没法存成源文件再打开」。
- 躲开「要改提示词或翻源码，才知道目录里有什么」。

### 比常见做法更好的地方

| 做法 | 常见痛点 | 言灵 v1.0.1 |
| --- | --- | --- |
| 对话直接出 HTML / React | 页面漂、难校验、难再打开 | 只出目录内的 A2UI JSON，渲染器决定长什么样 |
| 纯可视化搭积木 | 从空白开始慢，改结构费事 | 落地页和对话是主入口；图鉴只读，积木式工具只做工坊保底 |
| A2UI Studio / Composer | 卡片市场、多渲染器、Schema 生成器，范围大 | 只抄进门方式、图鉴、三个案例、通道设置；目录仍锁死 |
| 完整低代码 / 应用平台 | 重、要数据源和发布 | 仍只做一页稳定预览，范围小但契约硬 |

价值曲线上，v1.0.1 继续做高：校验、可重复打开、对话主路径。补高一件：进门和目录可见。继续做低：组件广度、真实数据、发布上线。

## 7. Solution

### 7.1 UX / 用户流程

工坊内部的主次、文案和纸页规范仍见 [Design v1.0.0](./Design.md)。v1.0.1 要在 Design 里补外壳（落地页、图鉴、案例、设置），本文先定信息结构和流程。

产品不再一打开就是工坊。外层是工作室壳，左侧四个入口：

```
┌──────┬─────────────────────────────────┐
│ 开始 │  落地页（大输入）                │
│ 创建 │  或工坊（说话 / 纸页 / 逃生舱）   │
│      │                                 │
│ 基础 │  组件图鉴                        │
│ 组件 │                                 │
│      │                                 │
│ 精选 │  三个案例：预览 + JSON           │
│ 案例 │                                 │
│      │                                 │
│ 设置 │  Base URL / Key / 模型名        │
└──────┴─────────────────────────────────┘
```

左侧导航始终可见。四个入口用文字，不只靠图标。工坊仍是书桌：笔记本、纸页、属性抽屉、排字抽屉。外壳不要做成第二套 IDE。

#### 开始创建：落地页 → 工坊

落地页是进门，不是聊天皮肤。

1. 打开产品，默认落在「开始创建」落地页。
2. 大标题说明从这里生成界面。输入框占主位置。占位符：**描述你想要的界面…**
3. 输入框下三个提示，与工坊空状态相同：
   - 做一个登录表单
   - 做一个设置页
   - 做一个带筛选的列表
4. 用户提交（回车、发送，或点提示）：进入工坊，并把这句话放进说话栏 **自动发送**。
5. 之后走 v1.0.0 工坊规则：先校验，再换纸页；失败则纸页不动，气泡说人话。

导航规则：

- 已在工坊时，再点「开始创建」留在工坊，不退回落地页。
- 工坊顶栏「新建」仍清空当前页和对话，并留在工坊（与 v1.0.0 相同）。
- 从基础组件 / 精选案例 / 设置回到「开始创建」：若已经进过工坊，打开工坊；若从未发送过、也未「用这一页」，打开落地页。

落地页 **不做**：传图识别、多行业提示胶囊、卡片市场入口。

#### 生成一页 / 再改一版 / 试一试 / 带走再打开

与 v1.0.0 相同，发生在工坊内。摘要：

1. 模型给出完整 JSON。系统先做目录校验。
2. 通过：画布换成新页面。气泡里只说一句人话。
3. 不通过：画布不动。气泡里说明哪条规则没过。
4. 再改一版时，把当前 JSON 交给模型，仍是整份替换。
5. 预览可填可点，结构不因点击而改变。
6. 下载的 JSON 再打开，预览必须与下载前一致。

#### 看一个基础组件

1. 点「基础组件」。左侧列出 18 个组件，分三组：布局、内容、输入。
2. 点其中一个。右侧依次是：短说明、Ant Design 预览、合法 JSON、属性表。
3. 用户可以复制 JSON。不能把这个组件插入当前工坊页。
4. 没有移动端 / PC 切换。预览宽度跟工坊纸页同一套渲染器。

#### 用一个精选案例

1. 点「精选案例」。看到三个案例卡片：登录表单、设置页、带筛选的列表。
2. 点开一个。看到该页的预览和完整 JSON。
3. 点 **用这一页**。若工坊里已有当前页，先确认：**换上这一页？当前页会被盖掉。** 确认文案可与「新建」同一家族：确认「换上」，取消「留下」。
4. 系统用同一道校验闸装入。通过则进入工坊，纸页就是这一页。对话线程按「新稿」处理，避免旧聊天改到装入的页上。
5. 不通过则工坊不动，并说明原因（案例夹具本身必须能通过；这条是防回归）。

#### 配通道

1. 点「设置」。三项：Base URL、API Key、模型名。
2. 保存后立刻对后续对话生效。不需要重启进程。
3. 页面标明当前生效来源：界面 或 环境变量。
4. Key 用密码框。保存后回看是掩码，不是明文。
5. 清空界面三项并保存，则下一次对话退回 `.env`。

### 7.2 关键功能

v1.0.0 的 F1～F7 全部保留。下面只写仍生效的要点，以及 v1.0.1 新增项。

#### F1. 对话生成与修改（保留）

- 对话是生成和修改页面的主入口。落地页的提交也是对话，只是发送发生在进入工坊之后。
- 每次落地都是整份 JSON 替换。
- 发给模型的上下文必须包含当前页面 JSON。
- 快捷提示至少覆盖三类黄金任务。落地页和工坊空状态用同一组文案。
- 「新建」会清空当前页和当前对话。

#### F2. 目录校验后才能写入画布（保留）

写入前至少检查：只使用允许的组件名、必须有 `root`、子节点只引用 id、属性落在允许范围、`surfaceId` / `catalogId` 与约定一致。

不通过则不修改当前快照；对话里用人话说失败原因。手改 JSON 走同一套校验。「用这一页」也走同一套校验。

#### F3. 稳定渲染（保留，不扩目录）

- 渲染器只实现 A2UI 基础目录，并用 Ant Design 绘制。
- 模型禁止按 antd 组件名或 antd 属性来写。
- 同一份通过校验的 JSON，在同一目录版本下，预览必须一致。
- 只渲染一个 surface。一份文档就是一页。

v1.0.0 / v1.0.1 允许的组件（共 18 个，分组只用于图鉴导航）：

| 组 | 组件 |
| --- | --- |
| 布局 | `Column`、`Row`、`List`、`Card`、`Tabs`、`Modal` |
| 内容 | `Text`、`Image`、`Icon`、`Video`、`AudioPlayer`、`Divider` |
| 输入 | `Button`、`TextField`、`CheckBox`、`ChoicePicker`、`Slider`、`DateTimeInput` |

v1.0.1 **不新增** 任何一个组件名。图鉴不得出现白名单之外的名字。

#### F4. 对话里只说人话（保留）

成功一句短确认，失败一句短说明。完整 JSON 不进对话气泡。图鉴和案例页可以展示 JSON，因为那两页的工作就是看协议。

#### F5. 预览可试、结构不变（保留）

输入写入本地数据模型。按钮等动作写入事件日志。不把动作送回模型，不请求真实接口。

图鉴和案例里的预览同样可看。是否可试填：案例预览与工坊相同，可试；图鉴预览以看清组件为准，不要求完整数据模型编辑。

#### F6. 当前稿自动保存，JSON 可下载 / 打开（保留）

浏览器自动保存当前稿。用户可以下载 / 打开 JSON。不做命名文档柜、云同步、账号。

#### F7. 工程师逃生舱（保留）

组件树、属性面板、底部 JSON / 数据 / 事件 / 错误。只出现在工坊里。图鉴、案例、设置页不放逃生舱。

#### F8. 工作室外壳与落地页（新增）

- 四个入口：开始创建、基础组件、精选案例、设置。
- 默认打开落地页。
- 落地页提交后进入工坊并自动发送。
- 刷新后：当前稿仍按 F6 恢复。若已有当前稿，打开产品可以直接进工坊（不要每次刷新都打回落地页，把稿藏起来）。

#### F9. 基础组件图鉴（新增）

每个组件一页，内容固定为四块：

1. **名称 + 一句中文说明**（说明它在页面里干什么，不写实现细节）。
2. **预览：** 用与工坊相同的 Ant Design 目录渲染一份最小合法文档。
3. **JSON：** 这份文档的源文件（`createSurface` + `updateComponents` + `updateDataModel`）。可复制。
4. **属性表：** 属性名和说明。以目录 schema 为准，不编造 antd 属性。

图鉴 JSON 必须能通过 `validateSnapshot`。它不是当前稿。浏览图鉴不得改工坊里的纸页。

#### F10. 精选案例（新增）

第一批只有三个，与 KR1 黄金任务相同：

| 案例 | 必须能看出 |
| --- | --- |
| 登录表单 | 含 `TextField`（含密码/遮盖）、主按钮、绑定数据 |
| 设置页 | 多项输入 + 用 `Column` / `Card` 分组 |
| 带筛选的列表 | `ChoicePicker` 或等价筛选 + `List` |

每个案例：卡片入口 → 预览 + 完整 JSON → **用这一页**。装入后的纸页必须与案例文件一致。案例文件与测试夹具应是同一份真源，避免两套例子。

不做行业分类、不做搜索、不做收藏。

#### F11. 设置：对话通道（新增）

可配三项，与现有环境变量同名含义：

| 项 | 对应 |
| --- | --- |
| Base URL | `OPENAI_BASE_URL` |
| API Key | `OPENAI_API_KEY` |
| 模型名 | `OPENAI_MODEL` |

覆盖规则：

- 界面里某项有非空值，对话用界面这项。
- 界面这项为空，用 `.env` 对应项。
- 界面三项都空，行为与 v1.0.0 相同，只认 `.env`。
- 界面有值但缺某一项时，缺的那一项仍可从 `.env` 补。三项拼齐才能发对话；拼不齐时说话栏要能看出「通道没配好」，不能静默失败成空白。

存储：

- 只存在浏览器本地（版本化 key，例如 `kotodama.channel:v1`）。
- 不写入下载的 JSON，不写入 `Snapshot`，不进仓库。
- 保存后的后续请求必须带上界面配置，本地代理优先用请求里的通道，没有再读 `.env`。

不做：渲染器切换、目录 URL 切换、连接诊断面板、多 Key 槽位。

### 7.3 技术

工坊闸门与 v1.0.1 外壳的实现契约见 [TRD](./TRD.md)。路由、图鉴 / 案例夹具、通道覆盖以 TRD 为准。这些选择影响产品契约，所以写在这里。

| 选择 | 决定 |
| --- | --- |
| 协议 | A2UI v0.9 消息：`createSurface`、`updateComponents`、`updateDataModel` |
| 外观 | Ant Design 绘制基础目录，不把 antd 全量组件暴露给模型 |
| 文档 | 一份 JSON 数组就是一页。JSON 是源文件 |
| 目录 | 基础目录带版本。v1.0.1 **不**扩展组件 |
| 落地 | 整份替换。先校验，后写入 |
| 产品壳 | 四个入口。工坊是「开始创建」的第二屏，不是唯一屏 |
| 图鉴 / 案例 | 仓库内夹具 JSON；图鉴每组件一份最小文档，案例三份黄金文档 |
| 模型通道 | 仍走现有本地对话代理。界面配置覆盖 `.env`。不绑定某一家模型品牌的设置 UI |

当前实现已具备工坊。v1.0.1 要补齐的是：外壳与落地页、18 组件图鉴、三个案例的预览和装入、通道设置及覆盖规则。不要借机改校验闸或扩大白名单。

### 7.4 Assumptions

下面这些是目前相信、但还没被证明的事。做的过程中要核对。

1. 基础目录足够做出登录、设置、带筛选列表这三类页面，观感能被接受。（v1.0.0 假设，仍有效）
2. 模型在「只输出合法 JSON、另给一句人话」的要求下，成功率够用。（v1.0.0 假设，仍有效）
3. 整份替换比补丁更不容易出错。页面还不大时，整份替换可以接受。
4. 用户能接受「预览可试，但不能真提交」。
5. 下载 JSON 再打开，对「带走」需求够用。
6. 落地页提交后立刻自动发送，比「先进工坊再点发送」更符合「从这里开始」。用户不会因为少一次确认而觉得失控。
7. 图鉴只读、不插入当前页，对 v1.0.1 够用。工程师要改结构，会去工坊说话或用手改。
8. 三个黄金案例作为精选已经够进门。不需要卡片市场的数量。
9. 通道配置存在浏览器本地可被接受。本产品是本地工坊，不是多人 SaaS。
10. 刷新时若已有当前稿，直接进工坊，不会让人觉得「首页丢了」。落地页只承担第一次进门和尚未开始时的进门。

若 1 或 2 不成立，应先缩小黄金任务或加强校验提示，而不是扩大目录。若 6 不成立，再改成「跳工坊并预填、不自动发送」。

## 8. Release

不写具体日历日。按相对顺序排。

### v1.0.0（已定契约，工坊必须继续满足）

必须有：

- 对话生成 / 再改一版（整份替换）
- 目录校验硬闸；失败保留旧页并用人话说原因
- 对话气泡不展示完整 JSON
- Ant Design 基础目录渲染，行为确定
- 预览可试填、可记事件；动作不回传模型
- 自动草稿 + 下载 / 打开 JSON
- 组件树、属性、JSON 作为逃生舱
- 三类黄金任务可重复验收，文件往返一致

### v1.0.1（当前版本，约 1 个迭代）

必须有：

- 工作室外壳：开始创建、基础组件、精选案例、设置
- 落地页大输入；提交后进工坊并自动发送
- 18 个基础组件图鉴：预览 + 合法 JSON + 属性表
- 三个精选案例：预览 + JSON + 「用这一页」
- 设置页三项通道；界面覆盖 `.env`；空则回退；Key 只存本地
- KR1～KR8 可验收
- 目录白名单与 v1.0.0 完全相同

没有也可以发 v1.0.1 的：

- 落地页更漂亮的动效（有标题、输入、三个提示即可）
- 图鉴属性表的交互式编辑（只读表即可）
- 设置页的「测试连接」按钮（说话失败时能看出没配好即可）
- 外壳深色与工坊深色的精细对齐（两者跟同一主题即可）

### 明确不做（以后再说）

| 以后 | 为什么现在不做 |
| --- | --- |
| 目录 v2（表格、完整表单、菜单等） | 会立刻拉低稳定性和成功率 |
| 图标列表 | 不是进门主路径；Icon 组件已在图鉴里 |
| 协议 / Schema 生成器 | 那是造目录，v1.0.1 只展示现有目录 |
| 多行业卡片市场、分类筛选 | 三个黄金案例已覆盖主路径 |
| 渲染器切换、其它 catalog URL | 言灵只认 Ant Design 基础目录 |
| 图鉴移动端 / PC 切换 | 一页一份 JSON，预览一种宽度即可 |
| 传图识别 | 主路径仍是说话，不是识图 |
| 增量补丁、流式边说边画 | 半份 JSON 会让页面闪和错 |
| 点击后把动作送回模型 | 页面会随对话漂，和「稳定」打架 |
| 真实接口、权限、登录态 | 那是应用运行时，不是页面生成器 |
| 多页、路由应用、多 surface | 超出「一页一份 JSON」（外壳路由不是应用多页） |
| 命名文档柜、云同步、协作 | 源文件先能下载打开即可 |
| 发布独立网址 / 导出 React 工程 | 第一问已定为后续 |

### 建议的验收顺序

1. 外壳能进：落地页、四个入口、刷新后当前稿不丢。
2. 落地页自动发送：三类提示都能进工坊并走现有对话闸。
3. 图鉴 18 个组件：预览能画、JSON 能过校验、没有新组件名。
4. 三个案例能预览；「用这一页」后工坊与夹具一致。
5. 设置覆盖 `.env`；清空后回退；Key 不进 JSON 文件。
6. 回归 v1.0.0：坏 JSON 仍不能成为当前页；文件往返仍一致；气泡仍只有人话。

做完这六步，v1.0.1 就算完成。
