# 言灵 PRD

**产品名称：** 言灵（kotodama）  
**文档版本：** v1.0.0  
**状态：** 已对齐，可作为 v1.0.0 开发依据

---

## 1. Summary

这份文档说明言灵 v1.0.0 要做成什么。

用户用说话生成或修改一份界面 JSON。渲染器按固定的组件目录，用 Ant Design 把这份 JSON 画成页面。同一份 JSON、同一个目录版本，永远画出同一页。页面能下载、能再打开，结果不变。

v1.0.0 不做上线发布，不接真实接口，也不做多页应用。

## 3. Background

### 现在是什么情况

仓库里已经有一个能跑的编辑器，产品名就叫「言灵」。

主链路已经通了：

1. 用户在左侧对话里描述界面。
2. 模型输出 A2UI v0.9 的 JSON。
3. 中间预览用 Ant Design 画出来。
4. 右侧可以改选中组件的属性。
5. 底部可以看到和手改 JSON。

组件目录是 A2UI 基础目录，不是完整的 Ant Design 组件表。提示词已经禁止模型按 antd 组件名和属性来写。预览里填表会改本地数据，点击会记到事件日志，不会把点击送回模型。

浏览器里会自动保存一份草稿。

### 为什么现在要写这份文档

现有实现更像一个能用的实验台，还不是一条说得清的产品契约。

几个关键缺口：

- 对话气泡里主要是 JSON，不像「说话做页面」。
- 模型输出坏了，对画布的保护不够硬。没有「先过目录校验，再整份替换；失败则旧页面不动」。
- 没有把 JSON 当可带走的源文件（下载 / 打开）。
- 目录没有产品意义上的版本。以后加组件时，旧页面可能画成另一副样子。
- 「稳定页面」和「能上线的应用」容易被混在一起。

A2UI 把界面收成一份可校验的协议 JSON。Ant Design 把这份 JSON 画成熟悉的样子。这两件事现在已经能接上。v1.0.0 要把这条路写成规则，而不是继续加功能。

## 4. Objective

### 目标

让人用说话做出一页稳定的界面。

稳定的意思是：

- 模型只改 JSON，不直接画 HTML。
- 渲染器只画目录里允许的组件。
- 同一份 JSON，打开多少次都一样。
- 校验不过，页面保持原样。

### 为什么重要

对使用产品的人：不用先学组件树，也能看到一页像样的表单或列表。

对公司和团队：把「对话做界面」做成可重复的能力。中间产物是协议 JSON，不是一次性的截图，也不是模型现场编出来的网页。

这和产品方向一致：先证明「说话 → 合法 JSON → 稳定预览」，再谈更大的目录、真实数据和上线。

### Key Results

| 编号 | 结果 | 衡量方式 |
| --- | --- | --- |
| KR1 | 三类黄金任务都能用对话生成，并能再改一版 | 登录表单、设置页、带筛选的列表。每次结果都能通过目录校验，预览与 JSON 一致 |
| KR2 | 坏输出不能毁掉当前页 | 故意用不在目录里的组件、缺 root、非法属性。画布保持旧 JSON。对话里用人话说清原因 |
| KR3 | 文件往返后页面不变 | 下载 JSON → 清空现场 → 再打开同一文件。组件树、文案和数据与下载前一致 |
| KR4 | 对话主路径不像在看代码 | 成功时气泡里只有一句确认。完整 JSON 只出现在画布、底部编辑器和下载文件里 |

## 5. Market Segment(s)

市场按「要完成的工作」划分，不按年龄或职级。

### 主工作：用说话做出一页能看的界面

这些人会说「做一个登录表单」「把按钮改成主色」「加一项筛选」。他们要马上看到页面，不想先写 JSON。

约束：

- 只能用 v1.0.0 的基础目录，不能点名 Table、Menu 等 antd 组件。
- 一页一份 JSON，没有多页和路由。
- 预览可以试填、试点，但不会提交到真实后端。

### 次工作：把页面核对成可保存的源文件

前端或熟悉协议的人要检查模型有没有写飞。他们需要组件树、属性和 JSON。出错时要能手改，然后继续用对话往下改。

约束：

- 手改和对话改的是同一份文档。
- 手改同样要过校验。不过就不能成为当前页。

### 明确不做的工作（v1.0.0）

- 把页面发布成独立网址。
- 做成会自己变的应用（点击后模型再改界面）。
- 接真实接口、权限、多人协作。

## 6. Value Proposition(s)

### 用户要完成的工作

- 把脑子里的界面说出来，立刻看到一页。
- 改一句，页面跟着改，而且改坏了还能停在上一版。
- 把这一页带走，以后打开还是这样。

### 用户会得到什么

- 一条清楚的主路径：说话 → 一句确认 → 预览更新。
- 一份可保存的 JSON。它就是页面本身，不是草稿备注。
- 熟悉的 Ant Design 外观，同时不被 antd 的全部属性淹没。

### 用户能躲开什么痛苦

- 躲开「模型写了一大段 HTML，每次都不一样」。
- 躲开「生成失败，当前页被盖掉」。
- 躲开「看起来能用，却没法存成源文件再打开」。

### 比常见做法更好的地方

| 做法 | 常见痛点 | 言灵 v1.0.0 |
| --- | --- | --- |
| 对话直接出 HTML / React | 页面漂、难校验、难再打开 | 只出目录内的 A2UI JSON，渲染器决定长什么样 |
| 纯可视化搭积木 | 从空白开始慢，改结构费事 | 对话是主入口，积木式工具只做保底 |
| 完整低代码 / 应用平台 | 重、要数据源和发布 | v1 只做一页稳定预览，范围小但契约硬 |

价值曲线上，v1.0.0 故意做高这三件事：校验、可重复打开、对话主路径。故意做低这三件事：组件广度、真实数据、发布上线。

## 7. Solution

### 7.1 UX / 用户流程

主界面保持三栏加底部，但主次必须明确。

```
┌──────────┬─────────────┬──────────┐
│ 对话 *   │   预览      │ 属性     │
│ （主）   │   画布      │ （逃生） │
│ 组件树   │             │          │
│ （逃生） │             │          │
├──────────┴─────────────┴──────────┤
│ JSON / 数据 / 事件 / 错误（逃生）  │
└───────────────────────────────────┘
```

打开产品时，左侧默认是对话，不是组件树。

#### 生成一页

1. 用户说「做一个登录表单」，或点快捷提示。
2. 模型给出完整 JSON。系统先做目录校验。
3. 通过：画布换成新页面。气泡里只说一句人话，例如「已生成登录表单」。
4. 不通过：画布不动。气泡里说明哪条规则没过。

#### 再改一版

1. 用户说「加上验证码」或「标题改成企业登录」。
2. 系统把当前 JSON 交给模型，模型再输出整份 JSON。
3. 同样先校验再替换。失败则停在改之前的那一页。

#### 试一试

1. 用户在预览里填表、点按钮。
2. 输入写入本地数据。点击出现在事件日志。
3. 页面结构不因为点击而改变。要改布局，只能再说话，或去逃生舱手改。

#### 带走再打开

1. 用户下载当前 JSON。
2. 之后打开这份文件。
3. 预览必须与下载前一致。

工程师需要时，再打开组件树、属性面板和底部 JSON。这三处改的是同一份文档，规则与对话落地相同：先校验，再成为当前页。

### 7.2 关键功能

#### F1. 对话生成与修改

- 对话是生成和修改页面的主入口。
- 每次落地都是整份 JSON 替换，不是补丁，也不是边生成边画。
- 发给模型的上下文必须包含当前页面 JSON，这样「再改一版」才有依据。
- 快捷提示至少覆盖三类黄金任务：登录表单、设置页、带筛选的列表。
- 「新建」会清空当前页和当前对话，避免旧聊天改到新稿上。

#### F2. 目录校验后才能写入画布

写入前至少检查：

- 只使用 v1.0.0 允许的组件名。
- 必须有 id 为 `root` 的根组件。
- `children` / `child` 只引用其它组件的 id，不内联嵌套一整棵树。
- 组件属性落在该组件的允许范围内。
- `surfaceId`、`catalogId` 与当前文档约定一致。

不通过则：

- 不修改当前快照。
- 对话里用人话说失败原因。
- 错误仍可在底部错误列表里查看。

手改 JSON 走同一套校验。校验失败时，编辑器可以提示错误，但不能把坏 JSON 变成当前预览的真相。

#### F3. 稳定渲染

- 渲染器只实现 A2UI 基础目录，并用 Ant Design 绘制。
- 模型禁止按 antd 组件名或 antd 属性来写。
- 同一份通过校验的 JSON，在同一目录版本下，预览必须一致。
- v1.0.0 只渲染一个 surface。一份文档就是一页。

v1.0.0 允许的组件：

`Column`、`Row`、`List`、`Card`、`Tabs`、`Modal`、`Divider`、`Text`、`Image`、`Icon`、`Video`、`AudioPlayer`、`Button`、`TextField`、`CheckBox`、`ChoicePicker`、`Slider`、`DateTimeInput`

#### F4. 对话里只说人话

- 成功：一句短确认，说明改成了什么。
- 失败：一句短说明，指出为什么没改。
- 完整 JSON 不进对话气泡。它属于画布、底部编辑器和下载文件。

#### F5. 预览可试、结构不变

- 输入组件把值写进本地数据模型。
- 按钮等动作写入事件日志。
- JSON 里可以保留 `action` 字段，为后续版本预留。
- v1.0.0 不把动作送回模型，不请求真实接口。

#### F6. 当前稿自动保存，JSON 可下载 / 打开

- 浏览器自动保存当前稿，刷新不丢。
- 用户可以下载当前 JSON 文件。
- 用户可以打开一份 JSON 文件，覆盖当前稿（仍须先校验）。
- v1.0.0 不做命名文档柜，不做云同步，不做账号。

#### F7. 工程师逃生舱

- 组件树：查看结构，插入、复制、删除。
- 属性面板：改当前选中组件。
- 底部：JSON、数据、事件、错误。
- 撤销 / 重做对对话落地和手改都生效。

逃生舱不能比对话更抢眼。默认焦点仍是对话和预览。

### 7.3 技术

这些选择影响产品契约，所以写在这里。

| 选择 | 决定 |
| --- | --- |
| 协议 | A2UI v0.9 消息：`createSurface`、`updateComponents`、`updateDataModel` |
| 外观 | Ant Design 绘制基础目录，不把 antd 全量组件暴露给模型 |
| 文档 | 一份 JSON 数组就是一页。JSON 是源文件 |
| 目录 | 基础目录带版本。v1.0.0 不扩展组件。以后加组件必须升目录版本 |
| 落地 | 整份替换。先校验，后写入。不做增量补丁，不做流式上画 |
| 模型通道 | 现有对话代理即可。v1.0.0 不绑定某一家模型品牌 |

当前实现已具备对话、预览、树、属性、JSON 编辑和本地草稿。v1.0.0 要补齐的是：目录校验硬闸、失败不覆盖、对话人话、JSON 文件下载/打开、目录版本、以及三类黄金任务的可重复验收。

### 7.4 Assumptions

下面这些是目前相信、但还没被证明的事。做的过程中要核对。

1. 基础目录足够做出登录、设置、带筛选列表这三类页面，观感能被接受。
2. 模型在「只输出合法 JSON、另给一句人话」的要求下，成功率够用。人话和 JSON 可以可靠拆开。
3. 整份替换比补丁更不容易出错。页面还不大时，整份替换可以接受。
4. 用户能接受「预览可试，但不能真提交」。
5. 下载 JSON 再打开，对 v1.0.0 的「带走」需求够用。多数人暂时不需要文档柜。
6. 同时服务非工程师和工程师时，只要默认打开对话，逃生舱放在旁边即可，不必做两套界面。

若 1 或 2 不成立，应先缩小黄金任务或加强校验提示，而不是立刻扩大目录。

## 8. Release

不写具体日历日。按相对顺序排。

### v1.0.0（当前版本，约 1～2 个迭代）

必须有：

- 对话生成 / 再改一版（整份替换）
- 目录校验硬闸；失败保留旧页并用人话说原因
- 对话气泡不展示完整 JSON
- Ant Design 基础目录渲染，行为确定
- 预览可试填、可记事件；动作不回传模型
- 自动草稿 + 下载 / 打开 JSON
- 组件树、属性、JSON 作为逃生舱
- 三类黄金任务可重复验收，文件往返一致

没有也可以发 v1.0.0 的：

- 更漂亮的空状态和引导（有三个快捷提示即可）
- 更细的属性表单体验
- 多模型切换 UI

### 明确不做（以后再说）

| 以后 | 为什么现在不做 |
| --- | --- |
| 目录 v2（表格、完整表单、菜单等） | 会立刻拉低稳定性和成功率 |
| 增量补丁、流式边说边画 | 半份 JSON 会让页面闪和错 |
| 点击后把动作送回模型 | 页面会随对话漂，和「稳定」打架 |
| 真实接口、权限、登录态 | 那是应用运行时，不是页面生成器 |
| 多页、路由、多 surface | 超出「一页一份 JSON」 |
| 命名文档柜、云同步、协作 | 源文件先能下载打开即可 |
| 发布独立网址 / 导出 React 工程 | 第一问已定为后续 |

### 建议的验收顺序

1. 校验闸门：坏 JSON 永远不能成为当前页。
2. 渲染稳定：同一份合法 JSON 反复打开，预览一致。
3. 对话主路径：三类黄金任务能生成、能再改；气泡里只有人话。
4. 文件往返：下载再打开，页面不变。
5. 逃生舱：手改与对话改同一份文档，规则相同。

做完这五步，v1.0.0 就算完成。
